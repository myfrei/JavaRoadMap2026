## Задания (по порядку)

### 1. `saveAuthorWithBooks` — каскадное сохранение (статьи 02–03)

**Задача.** Создай `Author`, добавь книги хелпером `addBook(...)` и сохрани весь граф
**одним** вызовом репозитория — книги по отдельности сохранять нельзя (за тебя работает `cascade`).

**Ожидаемый результат.** После одного `save` в базе автор и все его книги; метод возвращает
сохранённого автора с заполненным `id`.

### 2. `titlesOfAuthor` — ленивые коллекции (статьи 02, 05)

**Задача.** Найди автора по имени (derived query уже есть в `AuthorRepository`) и верни названия
его книг по алфавиту. Автор не найден → пустой список. Подумай: что произойдёт с `author.getBooks()`,
если метод выполнится вне транзакции, и какой аннотацией это чинится.

**Ожидаемый результат.** Для «Стругацких» из сида теста: `["Пикник на обочине", "Трудно быть богом"]`.

### 3. `authorsByBookCountDesc` — агрегирование (статьи 02–03)

**Задача.** Верни имена авторов по убыванию числа книг (при равенстве — по алфавиту).
Решай как удобнее: JPQL-запросом или загрузкой и сортировкой в памяти — но подумай,
что будет с каждым вариантом на миллионе авторов.

**Ожидаемый результат.** `["Стругацкие", "Лем"]` (2 книги против 1).

### 4. `renameBook` — обновление сущности (статья 05)

**Задача.** Загрузи книгу по id, поменяй название и добейся, чтобы UPDATE дошёл до базы.
Книга не найдена → `IllegalArgumentException`. Обрати внимание: внутри транзакции достаточно
изменить **управляемую** сущность — Hibernate увидит изменение сам (dirty checking).

**Ожидаемый результат.** После вызова и нового чтения из базы у книги новое название;
метод возвращает его же.

### 5. `seededGenres` — данные из миграций (статья 04)

**Задача.** Верни имена жанров по алфавиту через `GenreRepository`. Сами жанры в базу не вставляй —
они уже приехали из Liquibase-чейнджсета `v1.1-seed-genres.sql`.

**Ожидаемый результат.** `["Детектив", "Классика", "Фантастика"]` — доказательство, что миграции
накатываются и в тестах.

### 6. `countBooksPublishedSinceViaJdbc` — SQL руками (статья 06)

**Задача.** Посчитай книги с `publication_year >= year` через **`JdbcTemplate`** — без репозиториев
и сущностей. Параметр подставляй плейсхолдером `?`, не конкатенацией.

**Ожидаемый результат.** На сиде теста: с 1964 года — 2 книги, с 2000 — 0.

## 🎓 Навыки после модуля

- Проектируешь **сущности и связи** (`@OneToMany`/`@ManyToMany`, владелец связи, хелперы для двух сторон).
- Используешь **каскады и orphanRemoval** осознанно: сохраняешь граф одним вызовом.
- Пишешь **derived queries и JPQL** и понимаешь, когда коллекция ленивая и почему она взрывается вне транзакции.
- Понимаешь **dirty checking**: UPDATE без явного `save` внутри транзакции.
- Ведёшь схему через **Liquibase-миграции** (changelog, сид-данные) при `ddl-auto=validate`.
- Выбираешь между **JPA и JdbcTemplate**: ORM для домена, чистый SQL для отчётов.
