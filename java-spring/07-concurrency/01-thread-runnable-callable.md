# Лекция: Thread, Runnable и Callable

> Java Spring · Модуль 7 — Многопоточность в Java · [⬅ К содержанию трека](../README.md)

## Введение

Представьте кухню ресторана. Один повар (однопоточная программа) готовит блюда строго по очереди:
пока варится суп, салат не режется — все ждут. Добавим ещё трёх поваров — и заказы поедут
параллельно. Повар здесь — это **поток** (thread): независимая линия исполнения, которая делает
свою работу, пока остальные делают свою.

В этой лекции вы научитесь запускать потоки тремя способами, понимать их жизненный цикл и не
наступать на классические грабли вроде вызова `run()` вместо `start()`. Давайте разберёмся.

## Процесс против потока

Когда вы запускаете JVM (`java MyApp`), операционная система создаёт **процесс** — изолированный
контейнер со своей памятью. Внутри процесса живут **потоки** — они делят общую кучу (heap), но у
каждого свой стек вызовов и счётчик команд.

```
Процесс (JVM)
┌───────────────────────────────────────────────┐
│  Общая память (heap): объекты, статика         │  ← делится между потоками
│                                                │
│  ┌──────────┐  ┌──────────┐  ┌──────────┐      │
│  │ Thread 1 │  │ Thread 2 │  │ Thread 3 │      │
│  │  стек    │  │  стек    │  │  стек    │      │  ← свой у каждого потока
│  └──────────┘  └──────────┘  └──────────┘      │
└───────────────────────────────────────────────┘
```

Ключевой вывод: потоки **дёшево** общаются через общую память, но именно поэтому возникают гонки
данных — об этом будет отдельная лекция про Java Memory Model.

## Создание потока: extends Thread против implements Runnable

Первый способ — унаследоваться от `Thread` и переопределить `run()`:

```java
class DownloadThread extends Thread {       // ← заняли единственное наследование
    @Override
    public void run() {                      // ← код, который выполнит поток
        System.out.println("Качаю файл в " + Thread.currentThread().getName());
    }
}

new DownloadThread().start();                // ← start(), а НЕ run()!
```

Второй способ — реализовать `Runnable` (функциональный интерфейс) и передать его в `Thread`. Так
делают почти всегда:

```java
Runnable task = () -> System.out.println("Качаю файл");   // ← лямбда вместо класса
Thread t = new Thread(task);
t.start();
```

❌ Наследование от `Thread` «съедает» единственное наследование Java и смешивает *что делать* с
*как запускать*. ✅ `Runnable` отделяет задачу от механизма запуска — её можно отдать в пул потоков
(см. лекцию 3), переиспользовать и тестировать отдельно.

| Критерий | `extends Thread` | `implements Runnable` |
|----------|------------------|------------------------|
| Наследование | Занимает единственное | Свободно для другого класса |
| Разделение задачи и запуска | Смешано | Чисто разделено |
| Работа с пулами потоков | Нельзя передать в `ExecutorService` | ✅ Можно |
| Лямбда / method reference | Нет | ✅ Да |
| **Рекомендация** | Избегать | ✅ Предпочесть |

## Callable: когда нужен результат

`Runnable.run()` ничего не возвращает и не умеет бросать checked-исключения. Если задача должна
**вернуть значение** (или сообщить об ошибке), используют `Callable<V>` и получают результат через
`Future<V>`:

```java
import java.util.concurrent.*;

Callable<Integer> task = () -> {             // ← возвращает Integer
    Thread.sleep(100);                       // может бросить checked InterruptedException
    return 6 * 7;
};

ExecutorService pool = Executors.newSingleThreadExecutor();
Future<Integer> future = pool.submit(task);  // ← запустили, получили "обещание"

Integer result = future.get();               // ← блокируемся, ждём результат -> 42
System.out.println(result);
pool.shutdown();
```

`future.get()` **блокирует** вызывающий поток до готовности результата. Если задача бросит
исключение, оно прилетит обёрнутым в `ExecutionException`. ⚠️ Ограничения `Future` (блокирующий
`get`, отсутствие композиции) мы подробно разберём и обойдём в лекции 4.

## start() против run() — главная ошибка новичка

Самая частая ошибка в многопоточности — вызвать `run()` напрямую:

```java
Thread t = new Thread(() -> System.out.println(Thread.currentThread().getName()));

t.run();    // ❌ выполнится В ТЕКУЩЕМ потоке -> печатает "main". Нового потока НЕТ!
t.start();  // ✅ JVM создаёт новый поток -> печатает "Thread-0"
```

`run()` — это обычный метод: вызвали — выполнили здесь и сейчас. `start()` просит JVM **создать
новый поток**, который сам позовёт `run()`. Запомните: новый поток рождается **только** от
`start()`, и позвать его можно лишь один раз (повторный `start()` бросит
`IllegalThreadStateException`).

## Жизненный цикл потока

Поток проходит через состояния перечисления `Thread.State`. Вот они и переходы между ними:

```
         start()              получил CPU
  NEW ──────────▶ RUNNABLE ◀────────────────┐
                    │  │                     │
   ждёт монитор     │  │  wait()/join()      │ notify()/истёк таймаут/
  synchronized      │  │  sleep(t)           │ освободился монитор
                    ▼  ▼                     │
   BLOCKED ◀──┐  WAITING / TIMED_WAITING ────┘
              │
              └──────────── run() завершился ──────▶ TERMINATED
```

- **NEW** — объект создан, но `start()` ещё не вызван.
- **RUNNABLE** — выполняется или готов выполняться (ждёт квант CPU).
- **BLOCKED** — ждёт, когда освободится монитор `synchronized`.
- **WAITING** — ждёт бессрочно (`wait()`, `join()` без таймаута).
- **TIMED_WAITING** — ждёт с таймаутом (`sleep(ms)`, `wait(ms)`).
- **TERMINATED** — `run()` завершился (нормально или с исключением).

## Daemon-потоки, join() и interrupt()

**Daemon-поток** — фоновый «прислужник» (например, сборщик мусора). JVM не ждёт его завершения:
когда останутся только daemon-потоки, она выключается. Обычные (user) потоки, наоборот, держат JVM
живой.

```java
Thread heartbeat = new Thread(() -> { while (true) { /* пульс */ } });
heartbeat.setDaemon(true);   // ← JVM не будет ждать этот поток при выходе
heartbeat.start();           // setDaemon() нужно вызвать ДО start()
```

`join()` заставляет текущий поток дождаться завершения другого:

```java
Thread worker = new Thread(() -> System.out.println("работаю"));
worker.start();
worker.join();               // ← main ждёт, пока worker не закончит
System.out.println("worker точно завершён");
```

`interrupt()` — вежливая просьба остановиться (не насильное убийство). Поток сам обязан проверять
флаг и реагировать:

```java
Thread t = new Thread(() -> {
    while (!Thread.currentThread().isInterrupted()) {   // ← проверяем флаг
        // полезная работа
    }
    System.out.println("получил interrupt, выхожу чисто");
});
t.start();
t.interrupt();   // ← выставит флаг; sleep()/wait() при этом бросят InterruptedException
```

⚠️ Не «глотайте» `InterruptedException` пустым `catch`. Либо пробросьте его, либо восстановите флаг
вызовом `Thread.currentThread().interrupt()` — иначе сигнал отмены потеряется.

## Заключение

**Что изучено:**
- Разница процесса и потока: общая куча, отдельные стеки.
- Три способа задать работу потоку — `Thread`, `Runnable`, `Callable` — и почему `Runnable`
  предпочтительнее наследования.
- `Callable` + `Future` для задач с результатом и исключением.
- Жизненный цикл потока (NEW → RUNNABLE → WAITING/BLOCKED → TERMINATED).
- Daemon-потоки, кооперативная остановка через `interrupt()`, ожидание через `join()`.

**Как применять на практике:**
- Всегда описывайте задачу как `Runnable`/`Callable`, а не наследуйте `Thread`.
- Запускайте поток только через `start()`; `run()` — обычный вызов в текущем потоке.
- Реагируйте на `interrupt()` и не глотайте `InterruptedException`.

⚠️ И главное: **не создавайте потоки руками пачками** в продакшене. Создание потока — дорогая
операция, а тысячи потоков положат сервер. В реальных приложениях для этого есть пулы потоков —
именно с них мы продолжим после лекции про синхронизацию.

**Что дальше:** разберёмся, как нескольким потокам безопасно работать с общими данными.
