# Домашка модуля 7 — Многопоточность

> Статьи модуля: [оглавление](../README.md) · Примеры кода: [`src/main/java/...`](../src/main/java/com/javaroadmap/spring/s07/)

Чистая Java, без Spring. Заготовки лежат в
[`homework/src/main/java/.../homework/`](src/main/java/com/javaroadmap/spring/s07/homework/).
Сделай «красные» тесты [`Mod07HomeworkTest.java`](src/test/java/com/javaroadmap/spring/s07/homework/Mod07HomeworkTest.java)
зелёными. **Файл с тестами трогать не нужно.** Тесты детерминированы: общий старт потоков —
латчами; решения со `sleep` и «авось успеет» не пройдут.

## Как работать

1. Открой заготовку задания, прочитай TODO и формулировку ниже.
2. Реализуй задания по порядку.
3. После каждого задания запускай проверку:
   ```bash
   ./gradlew :java-spring:07-concurrency:homeworkTest
   ```
4. Цель — **зелёный** `homeworkTest`. Общий `./gradlew build` остаётся зелёным независимо от домашки.

## Задания (по порядку)

### 1. Потокобезопасный счётчик (статьи 02, 06)

`SafeCounter`

**Задача.** Реализуй `increment()`/`value()` так, чтобы счётчик не терял инкременты:
8 потоков × 25 000 одновременных инкрементов. Способ любой честный — `synchronized`,
`ReentrantLock` или атомик. Подумай, чем они отличаются (примеры: `Counters`).

**Ожидаемый результат.** Ровно 200 000 — каждый раз, а не «обычно».

### 2. Параллельный map (статья 03)

`ParallelMapper`

**Задача.** Применени функцию ко всем элементам через `ExecutorService` с заданным числом
потоков и верни результаты **в исходном порядке** (подсказка: `invokeAll` сохраняет порядок).
Пул должен закрываться при любом исходе.

**Ожидаемый результат.** Квадраты 1..100 в правильном порядке, без потерь и перестановок.

### 3. Композиция CompletableFuture (статья 04)

`AsyncCombiner`: `sumAsync`, `withFallback`

**Задача.** `sumAsync` — запусти оба supplier-а **параллельно** и сложи результаты
(`supplyAsync` + `thenCombine`). `withFallback` — ошибка не выходит наружу, вместо неё
запасное значение (`exceptionally`).

**Ожидаемый результат.** Тест `sumAsync` устроен как рандеву: каждый supplier ждёт второго —
последовательное выполнение просто зависнет. Fallback срабатывает только на ошибке.

### 4. Кто первый (статья 04)

`AsyncCombiner.firstOf`

**Задача.** Верни результат того supplier-а, который завершится первым
(`applyToEither`/`anyOf`). Проигравшего не ждать.

**Ожидаемый результат.** «Медленный» supplier держится латчем — побеждает «быстрый»,
и ответ приходит не дожидаясь медленного.

### 5. Виртуальные потоки (статья 04)

`VirtualBatch`

**Задача.** Выполни список `Callable` на виртуальных потоках
(`Executors.newVirtualThreadPerTaskExecutor`) и верни результаты в исходном порядке.

**Ожидаемый результат.** Все 100 задач выполнились на виртуальных потоках
(`Thread.currentThread().isVirtual() == true`), порядок результатов сохранён.

## 🎓 Навыки после модуля

- Пишешь **потокобезопасный код** и понимаешь цену каждого инструмента: монитор, lock, CAS.
- Распараллеливаешь работу через **ExecutorService** и корректно закрываешь пулы.
- Композируешь асинхронные шаги **CompletableFuture**-ами: параллельность, fallback, гонка за первым.
- Используешь **виртуальные потоки** для массовых блокирующихся задач.
- Понимаешь **JMM**: видимость, happens-before, зачем `volatile` (примеры: `StoppableWorker`).
- Узнаёшь **дедлок** по симптомам и предотвращаешь его порядком захвата замков
  (примеры: `DeadlockDemo`, `Account`).
- Пишешь **детерминированные тесты** конкурентного кода: латчи и рандеву вместо `sleep`.
