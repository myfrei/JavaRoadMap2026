# Инструменты сборки: Maven и Gradle

> Модуль 9 — DevOps · [к модулю](../../../course/09-devops.md)

## Зачем это нужно

Инструмент сборки превращает исходники в артефакт: качает зависимости, компилирует, гоняет тесты,
пакует jar. Без него команда тонет в ручных шагах и «у меня собирается, у тебя нет». Maven и Gradle —
два стандарта Java-мира; знать нужно оба.

**Где применяется в проектах:** каждый Java-проект; CI-пайплайны; управление версиями зависимостей;
многомодульные монорепозитории (как этот курс).

## Зависимости и репозитории

Обе системы качают библиотеки из репозиториев (Maven Central) по координатам
`group:artifact:version`:

```xml
<!-- Maven: pom.xml -->
<dependency>
    <groupId>org.junit.jupiter</groupId>
    <artifactId>junit-jupiter</artifactId>
    <version>5.11.4</version>
    <scope>test</scope>
</dependency>
```

```kotlin
// Gradle: build.gradle.kts
dependencies {
    testImplementation("org.junit.jupiter:junit-jupiter:5.11.4")
}
```

Транзитивные зависимости (зависимости зависимостей) подтягиваются автоматически.

## Lifecycle vs задачи

- **Maven** — фиксированный жизненный цикл фаз: `validate → compile → test → package → install`.
  Декларативно и единообразно, но негибко.
- **Gradle** — граф задач (tasks) с инкрементальностью и кэшем сборки. Гибче и быстрее на больших
  проектах, ценой более сложной модели.

```bash
mvn package                 # Maven: пройти фазы до package
./gradlew build             # Gradle: выполнить задачу build и её зависимости
```

## Многомодульный проект

Этот курс — Gradle-монорепо: `settings.gradle.kts` перечисляет модули, общий `build.gradle.kts`
задаёт единый конфиг (Java 25, JUnit) для всех. Версии зависимостей вынесены в version catalog
(`gradle/libs.versions.toml`) — одно место правды.

## Воспроизводимость

Чтобы «собирается у всех одинаково»:

- **wrapper** (`./gradlew`, `mvnw`) фиксирует версию самого инструмента сборки;
- версии зависимостей зафиксированы (никаких «динамических» `1.+`);
- сборка не зависит от локально установленных тулов (тулчейн скачивается, как Java 25 здесь).

В [homework](../homework/src/main/java/com/javaroadmap/m09/homework/Mod09Homework.java):

## Итог

**Что изучено:**
- Сборщик качает зависимости (`group:artifact:version`), компилирует, тестирует, пакует.
- Maven — фиксированный lifecycle; Gradle — гибкий граф задач с кэшем.
- Wrapper + зафиксированные версии = воспроизводимая сборка; version catalog для монорепо.

**Как применять на практике:**
- Коммитить wrapper и фиксировать версии — чтобы сборка была одинаковой у всех и в CI.
- Выносить версии в одно место (BOM/version catalog), не дублировать по модулям.
- Понимать оба инструмента: Maven чаще в legacy/enterprise, Gradle — в современных и больших проектах.
