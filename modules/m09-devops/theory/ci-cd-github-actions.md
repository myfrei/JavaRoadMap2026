# CI/CD на GitHub Actions

> Модуль 9 — DevOps · [к модулю](../../../course/09-devops.md)

## Зачем это нужно

CI (Continuous Integration) автоматически собирает и тестирует каждый коммит — баги ловятся за
минуты, а не в проде. CD (Continuous Delivery/Deployment) автоматизирует выкладку. Вместе они
убирают ручную рутину и «работало на моей машине»: проверка идёт в чистом, воспроизводимом окружении.

**Где применяется в проектах:** проверка PR перед мержем; автосборка образов; деплой в стейджинг/прод;
прогон линтеров и сканеров безопасности.

## Пайплайн = шаги в чистом окружении

```yaml
# .github/workflows/ci.yml
name: CI
on:
  pull_request:           # запускать на каждый PR
  push:
    branches: [ main ]

jobs:
  build:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4            # 1) забрать код
      - uses: actions/setup-java@v4          # 2) поставить JDK
        with:
          distribution: temurin
          java-version: 25
      - run: ./gradlew build                 # 3) собрать + протестировать
```

Каждый запуск стартует на свежей виртуалке — никаких «локальных» артефактов. Если `./gradlew build`
красный, PR нельзя мержить.

## Этапы типичного пайплайна

```text
commit → [lint] → [build] → [test] → [security scan] → [docker build/push] → [deploy]
```

Ранние этапы — быстрые и дешёвые (линт, юнит-тесты), тяжёлые (e2e, деплой) — позже. «Сломалось рано»
дешевле, чем «сломалось на проде».

## Кэш и матрицы

- **Кэш** зависимостей/Gradle ускоряет сборку (не качать всё заново):
  ```yaml
  - uses: actions/setup-java@v4
    with: { distribution: temurin, java-version: 25, cache: gradle }
  ```
- **Матрица** гоняет джобу на нескольких версиях/ОС параллельно (например, Java 21 и 25).

## Секреты — не в коде

Токены и пароли хранят в GitHub Secrets, а не в репозитории:

```yaml
      - run: ./deploy.sh
        env:
          DEPLOY_TOKEN: ${{ secrets.DEPLOY_TOKEN }}   # из защищённого хранилища
```

## Связь с кодом модуля

`homeworkTest` каждого модуля — идеальный кандидат для CI-шага: PR не проходит, пока домашка не
зелёная. А `dockerTag`/`isValidImageName` из
[homework](../homework/src/main/java/com/javaroadmap/m09/homework/Mod09Homework.java) — логика этапа

## Итог

**Что изучено:**
- CI собирает/тестирует каждый коммит в чистом окружении; CD автоматизирует выкладку.
- Пайплайн = упорядоченные шаги (checkout → build → test → scan → deploy); дешёвое раньше дорогого.
- Кэш и матрицы ускоряют/расширяют проверку; секреты — в защищённом хранилище.

**Как применять на практике:**
- Сделать `./gradlew build` (и тесты) обязательным гейтом на PR.
- Ставить ранние быстрые проверки, поздние — тяжёлые; кэшировать зависимости.
- Никогда не коммитить секреты — только через Secrets/переменные окружения.
