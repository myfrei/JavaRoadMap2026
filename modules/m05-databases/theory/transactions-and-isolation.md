# Транзакции и уровни изоляции

> Модуль 5 — Базы данных · [к модулю](../../../course/05-databases.md)

## Зачем это нужно

Транзакция — это «всё или ничего»: группа операций либо применяется целиком, либо откатывается.
Без неё перевод денег может списать со счёта, но не зачислить. А уровень изоляции определяет,
какие «аномалии» видят параллельные транзакции — это напрямую влияет на корректность под нагрузкой.

**Где применяется в проектах:** любые связанные изменения (заказ + позиции + оплата); переводы;
счётчики остатков; всё, где важна согласованность данных.

## ACID и транзакция в JDBC

```java
connection.setAutoCommit(false);          // выключаем авто-коммит — начинаем транзакцию
try {
    transfer(connection, fromId, toId, 100);   // несколько UPDATE
    connection.commit();                  // фиксируем ВСЁ разом
} catch (SQLException e) {
    connection.rollback();                // при любой ошибке — откат ВСЕГО
    throw e;
}
```

ACID: **A**tomicity (всё или ничего), **C**onsistency (инварианты сохранены), **I**solation
(параллельные транзакции не мешают), **D**urability (закоммиченное переживёт сбой).

## В Spring — декларативно

```java
@Transactional                            // открыть транзакцию на время метода
public void placeOrder(Order order) {
    orderRepo.save(order);
    inventoryRepo.decrease(order.items()); // если упадёт здесь — save тоже откатится
}
```

`@Transactional` оборачивает метод: успешный возврат → commit, исключение → rollback.

## Уровни изоляции и аномалии

Чем выше изоляция, тем меньше аномалий, но и меньше параллелизма:

| Уровень | Грязное чтение | Неповторяемое чтение | Фантомы |
|---------|:---:|:---:|:---:|
| READ UNCOMMITTED | возможно | возможно | возможно |
| READ COMMITTED *(default в PG)* | нет | возможно | возможно |
| REPEATABLE READ | нет | нет | возможно* |
| SERIALIZABLE | нет | нет | нет |

- **Грязное чтение** — увидел незакоммиченные чужие изменения.
- **Неповторяемое чтение** — один и тот же `SELECT` вернул разное в рамках транзакции.
- **Фантомы** — повторный запрос с условием вернул новые строки.

```java
connection.setTransactionIsolation(Connection.TRANSACTION_REPEATABLE_READ);
```

## Короткие транзакции

Транзакция держит блокировки. Долгая транзакция (особенно с обращением к сети внутри) блокирует
других и копит проблемы. Правило: **транзакции короткие**, без внешних вызовов внутри.

## Итог

**Что изучено:**
- Транзакция = атомарность + согласованность; `commit`/`rollback` или `@Transactional`.
- Уровни изоляции и три аномалии (грязное/неповторяемое чтение, фантомы).
- Чем строже изоляция — тем меньше параллелизма.

**Как применять на практике:**
- Оборачивать связанные изменения в одну транзакцию; откатывать при ошибке.
- Держать транзакции короткими, не делать HTTP-вызовы внутри них.
- Поднимать изоляцию (до REPEATABLE READ/SERIALIZABLE) только там, где аномалии реально вредят.
