# Индексы, EXPLAIN ANALYZE и sargability

> Модуль 22 — PostgreSQL · [к модулю](../../../course/22-postgres.md)

## Зачем это нужно

Один правильный индекс ускоряет запрос в сотни раз; один неудачный предикат — сводит индекс на нет.
Умение читать план запроса и подбирать индексы — главный навык, отличающий «работает на 100 строках»
от «работает на 100 миллионах».

**Где применяется в проектах:** любые запросы к БД под нагрузкой; разбор «тормозящих» эндпоинтов;
проектирование схемы; код-ревью SQL.

## Индекс — это отсортированная структура (B-tree)

Без индекса БД делает **seq scan** — читает всю таблицу. Индекс (по умолчанию B-tree) хранит значения
колонки отсортированными, поэтому поиск идёт за O(log n):

```sql
CREATE INDEX idx_users_email ON users (email);
SELECT * FROM users WHERE email = 'ann@example.com';   -- index scan вместо seq scan
```

## EXPLAIN ANALYZE — рентген запроса

`EXPLAIN ANALYZE` показывает реальный план и время:

```sql
EXPLAIN ANALYZE SELECT * FROM users WHERE email = 'ann@example.com';
-- Seq Scan on users  (... rows=1 ... actual time=18.2 ...)   ← плохо: читает всю таблицу
-- ... после CREATE INDEX ...
-- Index Scan using idx_users_email  (... actual time=0.04 ...) ← хорошо
```

Главное, что ищем глазами: **Seq Scan** на большой таблице по условию = кандидат на индекс;
переход к **Index Scan** = индекс работает.

## Sargability: предикат должен «дружить» с индексом

Sargable (Search ARGument ABLE) — предикат, который может использовать индекс. Функция **на колонке**
или `LIKE` с ведущим `%` ломают индекс:

```sql
WHERE email = 'x'           -- ✅ sargable
WHERE created_at > now()    -- ✅ sargable (диапазон по индексу)
WHERE lower(email) = 'x'    -- ❌ функция на колонке -> seq scan (нужен индекс по выражению)
WHERE name LIKE '%son'      -- ❌ ведущий % -> индекс бесполезен
WHERE name LIKE 'john%'     -- ✅ префикс -> индекс работает
```

Лечится переписыванием предиката или функциональным индексом
(`CREATE INDEX ... ON users (lower(email))`).

## Составной индекс: порядок колонок важен

В составном индексе сначала ставят колонки **равенства**, потом — **диапазона**:

```sql
-- запрос: WHERE city = 'NYC' AND status = 'ACTIVE' AND age > 18
CREATE INDEX idx_users_city_status_age ON users (city, status, age);
--                                              ^^^^^^^^^^^^ equality  ^^^ range
```

Правило: равенства (`=`) → потом диапазон (`>`,`<`). Диапазон в начале «обрезает» использование
последующих колонок индекса.

## Итог

**Что изучено:**
- Индекс (B-tree) превращает seq scan в index scan; читаем это в `EXPLAIN ANALYZE`.
- Sargable-предикаты используют индекс; функция на колонке и ведущий `%` — нет.
- Порядок колонок составного индекса: равенства перед диапазонами.

**Как применять на практике:**
- Перед добавлением индекса смотреть план (`EXPLAIN ANALYZE`), после — проверять переход к Index Scan.
- Переписывать не-sargable условия или делать функциональные/частичные индексы.
- Проектировать составные индексы под конкретные запросы, а не «на всякий случай».
